# A) Prompt kit (copy into `.forge/ai/prompts/`)

Keep these tiny. You’ll paste them into Claude Code or Cursor as needed (both happily consume file snippets). Variables in `<>`.

### `00-session-start.txt`

```
SESSION START — obey the Constitution.

Phase: <spec|plan|tasks|implement|merge|postmerge>
Task ID: <NNN-slug or NONE>

You SHALL:
1) Work diff-only and ask before apply.
2) Read ONLY these paths now: <comma-separated globs>.
3) Write ONLY to these paths now: <comma-separated globs>.
4) Link all work to Task <NNN or NONE>.

State your intended gate to pass and list the exact files you will read/write.
```

### `10-brainstorm.txt`

```
BRAINSTORM (temporary; never committed)
Goal: evolve the seed idea into a clear problem statement or kill it quickly.

Do:
- Elicit assumptions, constraints, tradeoffs.
- Produce 3–5 candidate approaches with risks.
- End with a Decision: pursue / defer / drop.

Output format (markdown bullets). Keep under 300 lines.
```

### `20-spec.txt`

```
SPEC FROM BRAINSTORM
Inputs: project/architecture/*, guidelines/*.

Produce:
- Problem statement (≤3 paras), out-of-scope bullets.
- Interfaces (high level), data boundaries, risks.
- 1–3 acceptance criteria (short sentences).

Do NOT write code. Cite the exact files you read.
```

### `30-plan-and-tasks.txt`

```
PLAN & TASKS
Inputs: spec, schemas/*.cue.

Produce:
- One-paragraph plan with milestones.
- A small set of tasks (≤1 day each): NNN-slug, type, acceptance items.
- For each feature task: draft PRD headings; fill ./tasks/NNN-slug/task.cue and acceptance.cue (diffs only).

Ask-before-apply. No code yet.
```

### `40-implement-tests-first.txt`

```
IMPLEMENT (TESTS FIRST)
Inputs: ./tasks/NNN-slug/*

Steps:
1) Propose test diffs that FAIL first; ask to apply.
2) After approval, propose implementation diffs to make tests pass.
3) Update docs/PRD if public surface changed.

Always generate unified diffs. Never touch brainstorms or CI secrets.
```

### `50-ask-before-apply.txt`

```
ASK BEFORE APPLY
I will propose a single unified diff. Confirm with:
  git checkout -b <NNN-slug>
  git apply --index /tmp/patch.diff
  <language test command>
If rejected, I will revise the diff.
```

### `60-mem-read-task.txt`

```
READ TASK MEMORY
Summarize the 3–7 most relevant memory entries for Task <NNN-slug> (ignore project memory unless pointed to). Cite entry IDs only; do not restate full text into the chat.
```

### `70-mem-suggest.txt`

```
SUGGEST MEMORY (WRITE-APPROVED BY HUMAN)
Propose ≤3 memory entries with: title, 2–3 sentence summary, file pointers. I will save or discard.
```

# B) Context contract (drop into `.forge/ai/context/policy.cue`)

This refines what you drafted earlier by adding **read/write scopes** and **memory gating** per phase.

```cue
package context

Phase: "brainstorm" | "spec" | "plan" | "tasks" | "implement" | "merge" | "postmerge"

policy: {
  brainstorm: {
    read:  ["./.forge/ai/brainstorms/**"]
    write: ["./.forge/ai/brainstorms/**"]
    memory: { project: false, task: false }
  }
  spec: {
    read:  ["./.forge/ai/project/architecture/**", "./.forge/ai/project/guidelines/**", "./.forge/ai/schemas/**"]
    write: ["./.forge/ai/project/architecture/**"]
    memory: { project: false, task: false }
  }
  plan: {
    read:  ["./.forge/ai/project/**", "./.forge/ai/tasks/*/**", "./.forge/ai/schemas/**"]
    write: ["./.forge/ai/tasks/*/task.cue", "./.forge/ai/tasks/*/acceptance.cue", "./.forge/ai/tasks/*/prd.md"]
    memory: { project: false, task: true }
  }
  tasks: {
    read:  ["./.forge/ai/tasks/*/**", "./.forge/ai/project/guidelines/**", "./.forge/ai/schemas/**"]
    write: ["./.forge/ai/tasks/*/**"]
    memory: { project: false, task: true }
  }
  implement: {
    read:  ["./.forge/ai/tasks/*/**", "./.forge/ai/project/guidelines/**", "./**"] // codebase allowed to READ
    write: ["./**", "!./.forge/ai/brainstorms/**", "!./.github/**", "!./.forge/ai/constitution/**", "!./.forge/ai/memory/project/**"] // but keep secrets/constitution/mem-proj read-only
    memory: { project: false, task: true }
  }
  merge: {
    read:  ["./**"]
    write: ["./.forge/ai/tasks/*/task.cue", "./.forge/ai/adr/**", "./.forge/ai/project/roadmap/**", "./docs/**"]
    memory: { project: true, task: true }
  }
  postmerge: {
    read:  ["./**"]
    write: ["./.forge/ai/memory/**", "./.forge/ai/tasks/*/task.cue", "./.forge/ai/project/roadmap/**"]
    memory: { project: true, task: true }
  }
}
```

> CI usage: fail a PR if modified files fall outside the `write` globs for the current phase (you can pass the phase via a label or a PR body marker). We already have the “no brainstorm files” and `cue vet` checks from Module 2—extend that script to validate these globs.

# C) Memory policy (read / write / expire)

**Goals**

* Local-only, file-based, repo-scoped.
* Two scopes: **project** (opt-in by human) and **task** (auto-read during `plan|tasks|implement`).
* **Read-only by default for agents**; agents propose entries, humans publish.

### Directory layout

```
.forge/
  ai/
    memory/
      project/
        index.cue
        M-0001.md
        M-0002.md
      tasks/
        001-local-cache/
          index.cue
          M-0010.md
          M-0011.md
      suggestions/            # agent writes forbidden; human can paste here
        20250908-1012-local-cache.md
```

### Typed schema (`.forge/ai/schemas/memory.cue`)

```cue
package schemas

MemoryEntry: {
  id:         =~"^M-[0-9]{4}$"
  scope:      "project" | { task: =~"^[0-9]{3}-[a-z0-9-]+$" }
  title:      string
  summary:    string // keep ≤280 chars by convention
  pointers?:  [...{ path: string, lines?: string, commit?: string }]
  tags?:      [...string]
  createdAt:  string // RFC3339
  createdBy:  "human" | "agent"
  status:     "suggested" | "published" | "archived"
  expiresAt?: string // RFC3339
}
```

### Index files

`memory/project/index.cue`

```cue
package memory
import "schemas"
entries: [...schemas.MemoryEntry]
policy: {
  ttlDays: 180   // default TTL for project entries
}
```

`memory/tasks/001-local-cache/index.cue`

```cue
package memory
import "schemas"
entries: [...schemas.MemoryEntry]
policy: { ttlDays: 90 }
```

### Example entry (`memory/tasks/001-local-cache/M-0010.md`)

```md
---

createdAt: 2025-09-08T10:12:00-07:00

```

> The front-matter is parsed by a tiny script (see below) and validated with `cue vet` against `schemas/memory.cue`.

### Read / write / expire semantics

* **Project memory**

  * **Read:** *off by default*. Only read when a human explicitly pastes `60-mem-read-project` (a variant of the read prompt) or points to specific entry IDs.
  * **Write:** human-only (paste a proposed entry, run `forge mem publish`).
  * **Expire:** default TTL 180 days; CI warns on expired-but-published entries.

* **Task memory**

  * **Read:** auto-summarized during `plan|tasks|implement` phases when present.
  * **Write:** human-approved; agent may only **suggest** via `70-mem-suggest.txt`.
  * **Expire:** default TTL 90 days after task marked “done” in `task.cue` → automatically archived.

* **Suggestions**

  * Agent never writes to disk; you copy/paste the suggestion into `memory/suggestions/…` and run `forge mem publish` to create a `M-####.md` under the proper scope.

### Tiny helper commands (sketch)

Add to `.forge/ai/scripts/forge-mem.sh` and call from CI/local:

```bash
#!/usr/bin/env bash
set -euo pipefail
cmd="${1:-}"; shift || true

case "$cmd" in
  publish)
    # Usage: forge-mem publish <scope:project|task:NNN-slug> <suggestion.md>
    scope="$1"; sug="$2"
    base=".forge/ai/memory"
    if [[ "$scope" == project ]]; then dir="$base/project"; else dir="$base/tasks/${scope#task:}"; fi
    id=$(printf "M-%04d" "$(find "$dir" -maxdepth 1 -name 'M-*' | wc -l)")
    out="$dir/$id.md"
    sed "s/^id: .*/id: $id/" "$sug" > "$out"
    echo "Published $out"
    ;;
  vet)
    cue vet .forge/ai/memory/**/index.cue .forge/ai/schemas/memory.cue
    ;;
  expire)
    # naive example: flag entries older than TTL
    grep -R --include 'M-*.md' -n '^createdAt:' .forge/ai/memory | awk '{print $1}'
    ;;
  *)
    echo "Usage: forge-mem {publish|vet|expire}"; exit 2;;
esac
```

Wire `forge-mem vet` into your CI alongside the existing `cue vet` steps.

## Allowed vs forbidden actions (agent)

**Allowed**

* Read only paths permitted by the current phase (policy.cue).
* Propose unified diffs; never apply without “ask-before-apply”.
* Propose memory entries (text), not files.

**Forbidden**

* Writing to `.forge/ai/constitution/**`, `.forge/ai/memory/project/**`, `.github/**`, or any secret-bearing paths.
* Committing brainstorming files.
* Deleting or neutering tests.
* Expanding public surface without an explicit justification and doc update.

## Claude Code & Cursor integration (practical)

* **How to use:** keep the **Constitution** and **00-session-start.txt** pinned; paste a single prompt at a time.
* **Context:** both tools read files you open or cite—point the agent explicitly to the files in each prompt (that’s why the session header asks you to list them).
* **Memory:** use `60-mem-read-task.txt` at the start of a work session on a task; paste **specific entry IDs** if you want more detail. Keep **project memory opt-in** to avoid overload.
