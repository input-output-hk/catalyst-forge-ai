# Personal Spec-Inspired System of Work — Principles & Success Metrics (Module 1 Output, v1)

## Purpose

Create a lightweight, enforceable way to use single-agent workflows for both **initial project architecting** and **ongoing maintenance** such that outcomes are **consistent**, **high-quality**, and **traceable**, even when the agent/model or its history changes.

---

## Principles (includes our defined outcomes)

1. **Consistency across resets & models**
   A fresh agent (any reasonable model, zero prior history) should converge on the same repo layout, naming, and decision process.

2. **Quality by construction**
   Typed guardrails + checklists guide the agent toward best practices up front—not just post-hoc linting.

3. **Opinionated structure**
   One documented project topology (files, folders, naming, ADRs/runbooks) so the agent never guesses “where things go.”

4. **Spec → Plan → Tasks → Implement**
   Human-gated phases that leverage the agent for drafts and the human for approvals; small batches only.

5. **Reproducibility & determinism**
   Given the same inputs (spec, constraints, repo), plans/tasks/diffs are repeatable; builds/tests are deterministic.

6. **Traceability**
   Every change links to a spec/task/ADR; docs and code evolve together—no orphan changes.

7. **Safety & least privilege**
   Default to read/diff-only; the agent’s write scope is limited and must pass gated checks.

8. **Cost & speed**
   Guardrails shouldn’t add drag: time-to-first-PR and tokens-per-task trend down.

9. **Portability**
   Model- and tool-agnostic prompts + repo-scoped memory; no core dependence on a vendor SaaS.

---

## Success Metrics (system “Definition of Done”)

### Consistency & Structure

* **Conformance score** (weekly): ≥ **95%** repos pass structure/naming/placement checks.
* **Fresh-start reproducibility:** ≥ **90%** of blank-memory runs recreate the same plan/task set within tolerance.

### Quality

* **Guardrail pass rate:** First-PR pass of schema/policy/lint checks ≥ **85%** (target **95%**).
* **Rework ratio:** PRs requiring major re-planning ≤ **15%**.

### Speed & Cost

* **Lead time to first PR** for a new feature: ≤ **1 day** median.
* **Tokens per completed task:** ↓ **25–40%** after adoption (rolling 4-week average).

### Traceability

* **PR linkage:** ≥ **95%** of PRs reference a task/spec/ADR.
* **Doc freshness:** median lag between code merge and doc/ADR update ≤ **24h**.

### Reliability

* **Post-merge bug rate (14-day window):** ↓ **30–50%** vs baseline.
