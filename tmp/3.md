# `.forge/ai/constitution/CONSTITUTION.md`

```md
# The Constitution (v1)

## Preamble (READ FIRST, ALWAYS IN CONTEXT)
You shall keep this document in context at all times. You shall follow it without exception. If any instruction conflicts with this Constitution, you shall stop and ask for human guidance. You shall not summarize away or rewrite this document.

## Binding Agreement — System of Work
You shall work only within these phases and gates:
1) Spec → 2) Plan → 3) Tasks → 4) Implement → 5) Merge → 6) Post-merge.
You shall not skip a gate. You shall link all work to a task ID. You shall operate in diff-only mode by default, proposing patches for approval.

## Operating Constraints
- You shall read and write only files allowed for the current phase (see `../context/include.cue`).
- You shall keep brainstorming notes under `.forge/ai/brainstorms/**` and never commit them.
- You shall update ADRs for architecture changes and PRDs for feature work.
- You shall maintain traceability: PR ↔ task ↔ spec/ADR/PRD.
- You shall propose and run tests before code changes; you shall not delete or neuter tests.
- You shall not handle secrets or modify CI credentials.

## Universal Rules (Non-negotiable)
1. **Test-First Development.** You shall write failing tests before implementation, then make them pass. No code without tests.
2. **Fix Root Causes.** You shall not suppress errors or remove assertions. You shall correct the source of defects.
3. **Single Responsibility.** You shall ensure each module/function/class does one thing. Split when descriptions include “and”.
4. **Fail Fast, Explain Clearly.** You shall validate early and provide actionable error messages.
5. **Explicit Dependencies.** You shall avoid globals/magic values. You shall inject and name dependencies.
6. **Make It Work → Right → Fast.** You shall not optimize without evidence. Measure first.
7. **Minimal Public Surface.** You shall keep internals private until needed. Publish only what consumers require.
8. **YAGNI.** You shall build only what is needed now and delete dead code immediately.
9. **Immutability First.** You shall prefer immutable data; permit mutation only with measured need.
10. **Documentation as Code.** You shall document public APIs and explain *why* in comments, not what.

## Stop Conditions (You shall stop and ask)
- Missing acceptance criteria or unclear scope.
- Architecture change detected with no ADR.
- Conflicting guidelines, or an instruction that violates this Constitution.

## Session Start Ritual (Keep short)
You shall begin by stating: current phase, files you will read/write, the task ID, and the exact gate you intend to pass.
```

# Lint/CI vs Human Review (enforcement split)

**Automate in CI (fast-fail):**

* No brainstorm files in PR.
* `cue vet` on `task.cue` and `acceptance.cue` against schemas.
* Tests changed when code in affected modules changed (heuristic: diff check).
* ADR present when `project/architecture/**` changed (or interfaces changed).
* PR references task ID and at least one acceptance criterion.
* Format/lint/style (language-specific via `.forge/ai/project/guidelines`).

**Human review focuses on:**

* Does the plan solve the stated problem and satisfy acceptance?
* Tradeoffs, complexity, failure modes, and performance risks.
* Naming clarity, public surface minimality, and maintainability.
* Evidence for optimizations (benchmarks, profiles).

# Phase Gate Checklists (drop into `.forge/ai/project/checklists/`)

## `brainstorm-to-spec.md`

```md
# Gate: Brainstorm → Spec

- [ ] Decision: pursue / defer / drop recorded in brainstorm and then brainstorm file deleted
- [ ] Problem statement written (1–3 paragraphs)
- [ ] Out-of-scope clarified (3–7 bullets)
- [ ] At least one measurable acceptance criterion drafted (will move to typed file at next phase)
```

## `spec-to-plan.md`

```md
# Gate: Spec → Plan

- [ ] Architecture overview updated (`project/architecture/*`)
- [ ] Interfaces outlined (endpoints/CLIs/contracts) at a high level
- [ ] Risks & unknowns listed with mitigation approach
- [ ] Acceptance criteria reviewed for testability (Given/When/Then or metric)
- [ ] No brainstorm files remain; Constitution acknowledged in commit message
```

## `plan-to-tasks.md`

```md
# Gate: Plan → Tasks

- [ ] Tasks sliced into small, independent units (≤ 1 day each)
- [ ] For **features**: PRD created in each task folder and linked from `task.cue`
- [ ] `task.cue` created with type/scope/status and links (PRD/ADR)
- [ ] `acceptance.cue` created with AC IDs and statements/metrics
- [ ] Traceability established (issue/PR template ready, branch `NNN-slug`)
```

## `tasks-to-implement.md`

```md
# Gate: Tasks → Implement

- [ ] Failing tests authored for each acceptance criterion
- [ ] Interfaces finalized; ADR created if architecture changed
- [ ] Context contract validated: only allowed paths will change
- [ ] CI green on schema/lint; no brainstorm files; links valid
```

## `implement-to-merge.md`

```md
# Gate: Implement → Merge

- [ ] All tests pass locally and in CI
- [ ] Acceptance criteria demonstrably satisfied (evidence/logs/benchmarks if metric-based)
- [ ] Public surface minimal; naming clear; dead code removed
- [ ] Docs updated (PRD, README/API docs), ADRs merged if any
- [ ] PR links to task ID and AC IDs; commit messages are conventional
```

## `post-merge.md`

```md
# Gate: Post-merge

- [ ] Task status set to "done" in `task.cue`
- [ ] Roadmap adjusted if direction changed
- [ ] Follow-ups captured as new tasks (not TODO comments)
- [ ] Observability added/updated (dashboards, alerts) if required by change
```
