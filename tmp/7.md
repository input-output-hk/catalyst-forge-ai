# Debug Guideline (Playbook)

Save as `.forge/ai/guidelines/debug.md`

```md
# Debug Guideline (Playbook)

## Purpose
A tight loop to turn unknown failures into a minimal reproduction, a verified fix, and a recorded lesson.

## Roles
- **Human:** gate changes, approve writes, decide scope.
- **Agent:** propose repros, diffs, and updates—diff-only.

## Loop (D → S → T → R → F → V → L)
1) **Detect**: capture the signal and scope.
2) **Stabilize**: stop the bleeding (feature flag, rollback, guard).
3) **Triage**: form 1–3 hypotheses; choose one to test first.
4) **Reproduce**: create a deterministic, minimal failing case (test/fixture).
5) **Fix**: make the failing test pass; keep changes small.
6) **Verify**: run full tests; add regression guard if warranted.
7) **Learn**: write/update a runbook and (if significant) a postmortem.

## Required Artifacts
- **Repro test/fixture** under `test/fixtures/<IR-or-task>/`.
- **Linked task** (type `bug`) with acceptance criteria.
- **Runbook** entry or update if this is repeatable class of failure.
- **Incident record** (IR) for Sev-worthy issues.

## Triage Notes (structured)
- **Signal:** error message/log line/alert id
- **Blast radius:** users, components, versions
- **First bad commit / env:** SHA, flags, data version
- **Hypotheses (≤3):** ranked, with quick falsifiers
- **Experiment plan:** exact steps/commands to prove/disprove

## Rules
- Write the **failing test first**; never neuter tests.
- Prefer **binary search** in history/config to isolate cause.
- If you can’t repro, capture **trace/log bundles** and **env snapshot** (OS, CPU, flags, seeds).

## Agent Prompts
- `debug-01-triage.txt`: “Summarize signals, propose ≤3 hypotheses, and one experiment.”
- `debug-02-repro.txt`: “Generate a minimal failing test/fixture; ask-before-apply.”
- `debug-03-fix.txt`: “Propose smallest diff to pass the test; cite files.”
- `debug-04-runbook.txt`: “Draft/patch runbook section; list verification steps.”

```

# Performance Guideline (Playbook)

Save as `.forge/ai/guidelines/perf.md`

```md
# Performance Guideline (Playbook)

## Purpose
Make performance work scientific: baseline → hypothesis → controlled change → compare → guard.

## Budgets & Baselines
- Budgets live in `schemas/project.cue` (`budgets.latency_p50_ms`, etc.).
- Store baseline measurements under `perf/baseline.json` (tool-agnostic).
- Compare with `perf/compare.json` produced by CI/local runs.

## Loop (B → H → E → C → G)
1) **Baseline (B):** capture p50/p95 and cost on a stable commit; pin data and flags.
2) **Hypothesis (H):** identify bottleneck with profiles/traces; state expected delta.
3) **Experiment (E):** single-variable change; run the same scenario.
4) **Compare (C):** diff vs baseline; accept only if it meets budget or improves without regressions.
5) **Guard (G):** add/adjust performance tests or thresholds to prevent backslide.

## Scenario Definition (reproducible)
- **Workload:** inputs, dataset snapshot, request mix
- **Environment:** hardware, container digest, feature flags, seeds
- **Success metrics:** what must improve or stay within tolerance

## Rules
- One change at a time; record the exact profile/trace and seed.
- No “optimizations” without measured gain; link to before/after results.
- Update runbook if a pattern is reusable (e.g., “hot path batching”).

## Agent Prompts
- `perf-01-baseline.txt`: “Generate the baseline plan + commands; produce JSON.”
- `perf-02-experiment.txt`: “Propose a single change with rationale and expected delta.”
- `perf-03-compare.txt`: “Summarize before/after; recommend accept/reject.”
- `perf-04-guard.txt`: “Propose a test/threshold to lock in gains.”
```

# Runbook template + typed schema

Save as `.forge/ai/runbooks/templates/runbook.md`

```md
---
id: RB-0000
area: "<service-or-area>"
owner: "<name-or-alias>"
last_verified: "2025-09-08"
severity: "low|medium|high|critical"
related_alerts: ["<id>", "<id>"]
related_dashboards: ["<link-or-path>"]
links: ["<IR-id>", "<ADR>", "<task>"]
---

# <Short Title>

## Symptoms
- What you see (exact log lines, metrics, alerts)

## Quick Checks (2-minute drill)
- Command(s) to quickly classify the failure

## Common Root Causes
- Cause → how to confirm

## Fix Steps (safe order)
1) …
2) …

## Validation
- How to prove it’s fixed (tests, metrics, traces)
```

Typed schema: `.forge/ai/schemas/runbook.cue`

```cue
package schemas

Runbook: {
  id:           =~"^RB-[0-9]{4}$"
  area:         string
  owner:        string
  last_verified: =~"^[0-9]{4}-[0-9]{2}-[0-9]{2}$"
  severity:     "low" | "medium" | "high" | "critical"
  related_alerts?: [...string]
  related_dashboards?: [...string]
  links?: [...string]
}
```

Runbook index: `.forge/ai/runbooks/index.cue`


# Retention & freshness rules (CI-enforceable, low-ceremony)

* **Runbooks must be fresh:** `last_verified` ≤ **90 days** old (configurable in `runbooks/index.cue`).

  * CI fails if any runbook is older (or unowned).
  * Verification is a **2-minute drill**: execute the Quick Checks against a known-good env and bump the date.
* **Incidents are immutable** once closed; follow-ups are tasks.
* **Perf baselines** must not be older than **30 days** if perf budgets exist; CI warns (not fails) when stale.

*Pseudo-steps to wire into CI (extend your existing workflow):*

```bash
# Fail on stale runbooks
cue eval .forge/ai/runbooks/index.cue | jq '.runbooks[]' | \
  your-check-staleness-script --ttl-days-from-cue

# Warn on perf baseline older than 30 days
test -f perf/baseline.json && your-check-json-date perf/baseline.json --ttl 30 || true
```

# Reproducibility protocol (applies to both debug & perf)

When you open a bug/perf task, you SHALL capture:

* **Commit & env:** git SHA, tool versions, container digest, OS/hw summary.
* **Flags & seeds:** feature flags, random seeds.
* **Data version:** fixture or dataset hash/snapshot.
* **Trace/profile:** one of: OTel trace, pprof/cProfile flamegraph.
* **Minimal test/fixture:** under `test/fixtures/<id>/` that fails (bug) or runs the scenario (perf).

This guarantees anyone (or any agent) can run the same experiment tomorrow and get the same result.
